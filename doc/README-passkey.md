# パスキー (WebAuthn) ログイン機能

## 概要

rep2のログインにパスキー (WebAuthn) を追加できます。
パスキーはパスワードの代わりになる (または併用できる) フィッシング耐性の高いログイン手段で、
認証には指紋や顔認証、PINを利用します。

## 動作要件

パスキーはブラウザのセキュアコンテキストでのみ動作します。

| 環境 | パスキー |
|---|---|
| HTTPS + 信頼された証明書(Let's Encrypt 等) | 利用可能 |
| HTTPS + オレオレ証明書 (警告を突破して表示) | 不可 |
| HTTPS + ローカルCA(mkcert 等)を信頼ストア登録済み | 利用可能 (その端末のみ) |
| http://localhost | 利用可能 (仕様上の例外) |
| LAN内HTTP(http://192.168.x.x等) | 不可 |
| ガラケー | 対象外 |

証明書エラーがあるとパスキー認証は動作しません。
対応ブラウザは Chrome / Edge / Safari / Firefox など。

`http://localhost` は HTTPS化していない環境でもパスキーを試せる例外です(`http://127.0.0.1` では利用できません)。

## 有効化

認証モードは `conf/conf_admin.inc.php` の `$_conf['passkey_auth_mode']` で設定します。

| 値 | モード | 動作 |
|---|---|---|
| 0 | 無効 (デフォルト) | パスキー機能を使用しない |
| 1 | 併用 | パスワード・Cookie保持・パスキーのすべてが有効 |
| 2 | パスキー専用 | パスワードとCookie保持を無効化。ログインはパスキーのみ |

passkey_auth_mode=2(パスキー専用)は、登録済みパスキーが1個以上あるときに実効化されます。
パスキーが 0 個のうちはパスワードログインとパスキーの登録が可能で、
1 個登録した時点でパスキー専用として機能し始めます 。

パスキーの最大登録数は `conf/conf_admin.inc.php` の `$_conf['passkey_max_registrations']` で変更できます (デフォルト 5)。

## パスキーの登録

1. rep2 にログインし、「ログイン管理」→「パスキー管理」を開く
2. 登録名を入力して「パスキーを追加」をクリックする
3. ブラウザの指示に従い、指紋・顔認証またはPINで認証する
4. 一覧に追加されれば登録完了

## パスキーでのログイン

ログイン画面の「パスキーでログイン」ボタンをクリックし、画面の指示に従って認証してください。
passkey_auth_mode=1(併用)の場合は、従来どおりのユーザー名・パスワードによるログインも引き続き利用できます。

## セッションのタイムアウト

パスキーでログイン、またはパスワードでログインするときに「Cookieにログイン状態を保持」を選択していないと、セッションによるタイムアウト制御になります。

* デフォルトは30分。無操作のまま放置するとログアウトになり、次のアクセスで再認証が求められます
* 操作を続けていればセッションは延長され続けます (スライディングウィンドウ)
* 失効までの時間は `conf/conf_admin.inc.php` の `$_conf['session_timeout_minutes']` で変更できます(分単位)
* session_timeout_minutesの制御はrep2側の制御であり、WEBサーバー側のセッションタイムアウト時間の方が短い場合はWEBサーバー側でタイムアウト判定されます

パスワードでログインするときに「Cookieにログイン状態を保持」を選択していると、30日間は再ログインなしで利用できます（従来の動作）。

## パスキーの削除

「パスキー管理」の一覧から削除できます。

* 削除するとrep2側のパスキーを削除します
* また、ブラウザがSignal APIに対応しており、かつ認証器側が個別削除に対応していれば認証器からパスキーが削除されます
* ブラウザがSignal APIに未対応の場合は認証器から別途削除しないとパスキーが残ります
* 個別削除に対応していないハードウェアキーの場合、ファクトリーリセットによる全削除でしかパスキーを削除できません

## 回復手順

パスキーをすべて失った場合 (すべての端末で初期化した場合等) は、
passkey_auth_mode=0(無効)や1(併用)に変更してください。
従来どおりのユーザー名・パスワードでログインできるようになります。

passkey_auth_mode=2(パスキー専用)のときに `data/pref/p2_passkeys.srd` を削除する方法もあります。
パスキーが 0 個になるとパスキー専用が維持できなくなり、
こちらもパスワードでログインできるようになります (そのまま登録し直せば専用モードに復帰します)。
