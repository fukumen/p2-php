# PHP intl 拡張モジュールについて

## 概要

rep2 は、検索ワードやスレッドタイトルの文字揺れ（全角/半角、丸数字、組文字など）を吸収して比較するために、PHP の intl 拡張モジュールを利用できます。

intl 拡張モジュールがない環境でも rep2 は動作しますが、一部の機能で精度が変わります。この文書では、intl がある場合とない場合の動作の違いを説明します。

## intl がある環境とない環境

* intl がある: 文字の正規化が Unicode の標準的な方法で行われ、最も正確に動作します。
* intl がない: intl の代替として簡易的な変換で代用されます。日常的な検索ではほとんど差はありません。

どちらで動作しているかは、`php -m` の出力に `intl` があるかどうかで確認できます。

```console
$ php -m | grep intl
intl
```

docker-rep2 および rep2-allinone をお使いの場合は intl が同梱されているため、この違いを意識する必要はありません。

## 動作の違い

### 自然文検索（similar 検索）

スレッド一覧の検索方法で「自然文」を選んだ場合、rep2 は検索ワードとスレッドタイトルを単語に分割して、似ているスレッドを探します。この単語分割の下地になるのが文字の正規化です。

intl がある場合は、丸数字（①②…）、組文字（㌔・㍑など）、ローマ数字（ⅠⅡⅢ…）も、対応する通常の文字（`1`、`キロ`、`ii` など）として扱われるため、こうした文字を含むタイトルも正確にヒットします。

intl がない場合は、これらの文字が元の形のまま扱われます。たとえば「④設定ガイド」という自然文検索は、intl があると `4設定ガイド` として扱われ `iv設定ガイド` というタイトルにヒットしますが、ない環境ではヒットしにくくなります。

影響するのは次の点です。

* 類似スレッド検索のヒットの正確さ
* 検索結果に表示される類似度（% 表記）の値
* 類似度による並び順
* 検索ワードがタイトル内で強調表示される範囲

かな・カナ・英数字の全角/半角の違いや、半角カナの濁点（ｶﾞ と ガ）については、intl の有無に関係なく同じように吸収されます。

### 画像アップロード時のファイル名（IC2）

Mac の Safari から画像をアップロードすると、ファイル名の濁点（゛）が分離した状態で送られてくることがあります。rep2 はこれを自動的に結合して元の読みやすいファイル名に戻します。

intl がある場合はすべての文字が正しく結合されます。intl がない場合は、まれに「ヴ」が「ェ」のように異なる文字に変わることがあります（「う」行の濁音・半濁音のみ）。

## 補足

* intl 拡張モジュールは PHP の標準機能ではなく、環境によってはインストールされていません。追加する方法は利用環境（パッケージ名や設定方法）に依存するため、お使いの環境のドキュメントを参照してください。
* docker-rep2 および rep2-allinone をお使いの場合は、intl が含まれた環境を利用するため追加作業はありません。
